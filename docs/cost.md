# ค่าใช้จ่าย (โครงประมาณการ — ต้องตรวจราคาปัจจุบันก่อนสรุป)

> **ห้ามอ้างว่า "ฟรี" เพราะเก็บรูปใน Drive** — บริการประมวลผลที่เปิดพร้อมใช้งานมีค่าใช้จ่ายจริง
> ตัวเลขด้านล่างเป็น **โครงรายการที่ต้องกรอกจากราคาปัจจุบันของบัญชีที่ใช้** ไม่ใช่ค่ารับประกัน

## รายการค่าใช้จ่ายที่ต้องคิด

| รายการ | ตัวขับค่าใช้จ่าย | หมายเหตุ |
|---|---|---|
| **Cloud Run — API** | vCPU·วินาที + หน่วยความจำ·วินาที + จำนวน request | ถ้าตั้ง **min-instances ≥ 1** เพื่อลด cold start จะมีค่า **ตลอดเวลา** แม้ไม่มีคนใช้ |
| **Cloud Run — Worker** | เวลารันตอนเตรียมรูป (มาก ๆ ตอน batch แรก) | ใช้ Cloud Run **Job** ให้จ่ายเฉพาะตอนรัน |
| หน่วยความจำต่อ instance | โมเดล + ดัชนี (เผื่อ 2 รุ่น) + แคชรูปย่อ | กำหนด RAM ให้พอ (ดู performance-plan) |
| Egress / เครือข่าย | ดาวน์โหลดต้นฉบับ + รูปย่อ | รูปใหญ่ = egress สูง; รูปย่อช่วยลด |
| Google Drive API | จำนวนคำขอ (list/get/download) | อยู่ในโควตาโปรเจกต์; เกินอาจถูก throttle |
| Container Registry / Artifact Registry | เก็บ image | เล็กน้อย |
| Logging/Monitoring | ปริมาณ log | ตั้ง retention ให้เหมาะ |
| พื้นที่ Drive | ต้นฉบับ + รูปย่อ + ดัชนี | ตามแพ็กเกจ Workspace/Shared Drive |

## ตัวแปรที่ทำให้ค่าใช้จ่ายต่างกันมาก
- **min-instances**: 0 = ประหยัดสุดแต่ cold start ช้า; ≥1 = เร็วแต่จ่ายตลอด
- **max-instances + concurrency**: คุมเพดานค่าใช้จ่ายและยอดคำขอ Drive รวม
- ขนาดรูปต้นฉบับ (ยิ่งใหญ่ egress ยิ่งสูง)
- จำนวนกิจกรรมที่โหลดค้างใน RAM พร้อมกัน

## วิธีประมาณก่อน deploy
1. เลือกค่า vCPU/RAM/min/max instances และ concurrency (จาก performance-plan)
2. เปิด [Google Cloud Pricing Calculator](https://cloud.google.com/products/calculator) กรอกค่าจริง
3. ประมาณ Drive API request/เดือนจาก pattern การใช้งาน (ค้นหา × ผู้ใช้ × รูปย่อ/หน้า)
4. รายงานเป็นช่วง (ต่ำ/กลาง/สูง) พร้อมสมมติฐาน — ไม่ใส่ตัวเลขเดียวเป็นคำรับประกัน

## ลดค่าใช้จ่าย
- ใช้รูปย่อ + แคช RAM ลดการดึง Drive และ egress
- Worker เป็น Job (จ่ายเฉพาะตอนเตรียมรูป)
- min-instances ตามช่วงเวลางาน (เช่นตั้ง ≥1 เฉพาะวันงาน)
- exact search เพียงพอที่ขนาดนี้ (ไม่ต้องจ่ายค่าโครงสร้าง ANN เพิ่ม)
